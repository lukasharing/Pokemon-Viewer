# Consolidated editor UI audit — 2026-07-29

This audit covers the visible web product on desktop and tablet. It evaluates
the shared structure separately from the accuracy of family-owned ROM
decoders. The visual shell is shared; GBA, Gen I and Gen II binary logic remains
physically isolated.

“Pass” here means the editor opens with a valid default document, remains
inside its workspace, has no page-level horizontal overflow, has no visible
control/text overflow, and presents its primary object before supporting
attributes. It does not upgrade a partial ROM decoder to verified.

The browser pass used Pokémon Emerald Rev. 0 and Pokémon Blue Rev. 0. Every
available editor was opened after a real ROM upload at both viewports. The
disabled Animation surface was not presented as working.

## Structural result

Every maintained editor now uses the same four semantic roles:

| Role | Meaning | Examples |
|---|---|---|
| Primary view | the object being edited | map, sprite canvas, battle scene, species, move profile, audio timeline |
| Attributes | values for the current selection | map/event properties, sprite palette, move record, sound parameters |
| Actions | commands on the current object | edit, apply, open related resource |
| Toolbox | direct manipulation and view modes | select, pan, paint, grid, zoom, undo/redo |

Shared SCSS owns these roles in `scss/components/_editor-workspace.scss`.
Persistent rails use `UiPanel`; contextual detail uses `UiWindow`. The layer
order is tokenized as panel, window, toolbox, then product overlays.

## Editor findings and corrections

### Hex

- Bytes remain the primary surface.
- Translation is a companion pane.
- Multi-character game-text tokens are clipped inside their native byte cell
  and retain a title/accessible label instead of bleeding across columns.

### Code

- Address/source controls form a compact document bar.
- Source and disassembly form the primary split.
- Tablet reflows the source controls and panes without overlapping actions.

### Map

- The map remains the dominant surface.
- Banks/navigation, history, encounters and properties are explicit panels.
- They share one bounded panel stack: Encounters keeps a readable body, Maps
  receives the remaining height and scrolls internally, and Properties is
  capped. Long lists cannot overlap their sibling panels.
- Blocks and contextual inspectors are windows.
- Paint/select/pan/zoom are toolboxes.
- The Generation I border pattern is a compact property window showing the
  single native 4 × 4-tile block. It reuses the Blocks browser for the full
  block set instead of duplicating a large tileset atlas over the map.
- Minimap changes the entire document context: normal-map windows and
  panels are hidden; only Minimap tools and selected-location attributes
  remain. Returning restores map properties and window state.

### Sprite

- Source selection is a compact full-width bar.
- The canvas is the primary view and the inspector is secondary.
- Undo, redo, zoom, native size, grid and pencil moved from an editor header
  into a floating canvas toolbox.
- Live composition, palette and properties use the shared panel/window
  material.

### Battle

- The native scene is full-width and owns the available stage.
- Trainer/team/engine information is a compact full-width supporting panel
  below the scene.
- Inspect, grid and timeline navigation are a canvas toolbox.
- Family screen ratios remain driver-owned, so Gen I 160×144 and GBA 240×160
  do not distort one another.

### Pokédex

- Species and sprite-side selection are a compact library bar.
- Native sprite, entry and cry are one primary Species document.
- Attributes, evolution, TM/HM and learnset are supporting panels.
- Long move names truncate inside their own control rather than pushing the
  panel wider.

### Moves

- Search and move selection remain compact.
- The semantic battle profile and animation link are the primary view.
- Fixed-record fields and references are supporting panels.
- Tablet action labels collapse to icon buttons with accessible names.

### Sound

- Audio is now the primary surface: playback/audition control, position,
  command/channel timeline and track list share one document.
- Sound parameters moved to an attributes panel; editing lives with those
  attributes.
- References form a supporting panel and decoded commands remain advanced.
- Verified Pokémon cry parameters can be auditioned. Documents without a
  decoded native playback path disable Play and do not synthesize a fake song.

### Encounters

- Area/method search is a compact library bar.
- Encounter methods are visible groups of subtables, not mutually exclusive
  dropdown choices. A user can compare grass, water, fishing and special
  sources without changing context or losing their scroll position.
- Native species sprites, probability and level are the primary slot view.
- Table ownership and pointers are supporting attributes.
- Pokédex, Battle and Edit remain contextual actions.

## Deliberate capability boundaries

- Native song playback is not claimed where channel execution is still
  partial. The Sound Editor shows decoded tracks/commands and disables playback
  instead of falling back to invented audio.
- Animation remains disabled for profiles without an editor-grade native
  command decoder.
- Visual validation does not turn partial table coverage into verified
  read/write coverage.

## Regression rules

1. New editor UI must compose shared roles and shared components before adding
   local CSS.
2. A visual editor's primary view occupies at least 50% of the usable default
   workspace.
3. No editor-local `z-index` may bypass the shared layer tokens.
4. Context changes update panels, windows, attributes and toolboxes together.
5. GBA, Gen I and Gen II drivers remain physically separate and are tested
   independently behind the shared document contract.

## Overflow/accessibility verification pass

The editor-by-editor desktop pass found and corrected four structural defects:

- Encounter slot rows were 220 px tall while their real contents required
  roughly 252 px, causing actions and probability rows to overlap the next
  card. Slots now use intrinsic grid rows and a content-derived minimum.
- Nerd-mode Code properties were clipped to 100 px with hidden overflow.
  Their region now owns a bounded vertical scroll instead of discarding rows.
- Hex toolbar sizing added its padding outside a forced 100% width and pushed
  the workspace horizontally. The toolbar and footer now remain inside the
  root's min-width contract.
- Inputs that relied on visual proximity alone now have explicit accessible
  names in Hex, Code, Sprite, Battle, Sound, and Encounters.

The shared `UiPanel` material now also owns a real footer primitive. Panel
actions can remain outside a scrolling body without editor-specific absolute
positioning.

## Clean-room editor pass — 23:08 KST

A second browser pass reloaded the application from an empty state, uploaded
Pokémon Emerald and Pokémon Blue independently, and opened every available
editor in navigation order. This pass did not reuse the previous DOM state.

The same checks were applied to Hex, Code, Map, Sprite, Battle, Pokédex, Moves,
Sound and Encounters:

- the document body has zero unintended horizontal overflow;
- every explicit internal scroll owner reaches both its first and last row;
- long status text is contained without resizing its panel;
- docked windows and panels retain a zero `min-width`/`min-height` contract;
- all visible icon-only controls have an accessible name;
- focus outlines are visible on shared window and panel controls;
- lists use intrinsic rows and do not stretch a single record to fill a panel;
- switching editors preserves the application shell and does not leave a
  family-specific overlay visible in another editor.

Corrections made during this pass:

- bumped the shared gesture module URL so an already-cached pre-pinch version
  cannot throw `GestureZoom.bindPinch is not a function` in every editor;
- made `UiPanel` bodies and docked `UiWindow` content the sole bounded scroll
  owners, with contained overscroll;
- added shared long-value wrapping and focus-visible behavior;
- constrained Battle's visual row to the native scene aspect and gave the
  lower source/team/engine area the remaining axis;
- stopped one-member Battle parties from stretching across the entire lower
  workspace;
- restored the Battle toolbox as a true overlay even after declarative
  `UiToolbar` enhancement;
- contained Pokédex cry and Sound document status text.

The intentionally larger-than-viewport Map canvas and horizontally scrollable
Pokédex evolution line remain internal scroll surfaces. They do not count as
page overflow and were verified to retain reachable content.
