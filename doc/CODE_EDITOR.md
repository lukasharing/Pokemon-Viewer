# Code editor guide

Open Code Editor directly or follow **Open script/Open text** from a map event.
A direct open always starts at offset zero in **Original CPU code** because that
address is a ROM header/vector table, never a proven event or text script.
Semantic EVENT/TEXT mode starts only from a typed resource link or an explicit
viewer choice. The loaded profile still selects the correct family codec and
default semantic language; codecs are never mixed between families.

## Views

- **Event script** decompiles recognized commands into an editable ROM-hacking-oriented source view.
- **Original CPU code** shows ARM/Thumb instructions for GBA and a complete
  LR35902/CB-prefix decompilation for GB/GBC.
- Red/Blue does not have a generic event-command bytecode like Generation III
  or Crystal. Its executable map logic is LR35902 code authored in RGBDS
  assembly. The editor therefore emits byte-exact RGBDS `db` source with the
  decoded instruction beside each record instead of inventing XSE-like
  commands that do not exist in the game.
- Gen I text uses editable pret-style RGBDS text macros; executable `text_asm` entries open as CPU code.
- Red/Blue also recognizes the top-level dispatcher macros from
  `pret/pokered`: `script_pokecenter_nurse`, `script_mart`,
  `script_bills_pc`, `script_players_pc`, `script_pokecenter_pc`,
  `script_prize_vendor`, `script_cable_club_receptionist`, and
  `script_vending_machine`. `script_mart` accepts a comma-separated item list;
  PUSH generates its count and `$FF` terminator.
- Crystal uses a separate `pret/pokecrystal` RGBDS text codec. Its command set
  includes Gen II-specific macros such as `text_buffer`, `text_today`, and
  `text_far` (`$16`); it never loads the Gen I `$17` interpretation.
- Crystal map events use a distinct event codec covering the complete
  `ScriptCommandTable` from `$00 scall` through `$A9 checksave`. Commands render
  with the macro names from `macros/scripts/events.asm`; variable `givepoke`
  records preserve their optional nickname and original-trainer pointers.
- When a Crystal command references dialogue (`writetext`, `farwritetext`,
  `jumptext`, or `winlosstext`), a compact resource bar appears below the tabs.
  Its buttons open the referenced text in an editable TEXT tab. The link retains
  the exact near/far owner fields, so applying a larger text can relocate it and
  update the original script pointer safely.
- Flow-control commands expose **Script** resource buttons as well. GBA
  `call`/`goto` branches retain their 32-bit pointer operand; Crystal calls,
  jumps, conditional branches, `sdefer`, and `stopandsjump` retain their
  same-bank or far pointer fields. Opening one creates another EVENT tab and
  permits safe relocation through the originating operand.
- A nearby forward GBA `goto`/`vgoto` is also expanded in the current source
  document. Its destination receives a stable `script_XXXXXX` label and
  decoding continues there, so a short entry block no longer hides the main
  event body. Any bytes physically located between the branch and destination
  are emitted as explicit `db` data and compile back unchanged. Targets outside
  the bounded document remain separate **Script** resources; the editor does
  not merge distant, potentially shared ROM regions into one unsafe patch.
- The Generation III table covers the complete `pret/pokeemerald`
  `gScriptCmdTable`, opcodes `$00` through `$E2`, using the operand widths and
  macro names from `asm/macros/event.inc`. Commands after `$CC` (including
  `messageinstant`, `pokenavcall`, white-fade warp, trainer buffers, contest
  buffers, and plural item names) are decoded and compiled rather than treated
  as unknown bytes.
- On a real GBA ROM, semantic code/text/movement/native pointers are checked
  against the cartridge address range while decoding. An impossible pointer
  stops the operation with a persistent notification instead of presenting
  random header, graphics, or compressed bytes as plausible event source.

The editor header's **View** menu switches between **Event / text source** and
**Original CPU code**. It opens or reuses a tab at the active address instead
of replacing the current tab, so an unapplied draft remains available when
moving between semantic source and raw CPU bytes. The Viewer selector in the
sidebar controls the same API.

Apply source patches only after reviewing the generated bytes. GBA event macros,
Gen I RGBDS text macros, RGBDS `db` source, and raw GBA CPU directives
participate in undo/redo.
Scripts opened from a map event carry their owning pointer: if compiled source
grows, PUSH allocates verified `$FF` free space and updates that pointer
atomically. GBA uses a 32-bit ROM pointer; Gen I preserves same-bank pointers
and updates both parts of `text_far`.

Following a Gen I `text_far` resource button opens its banked target and keeps
the exact address and bank fields as the owner. Digits inside quoted text remain
ordinary characters even though their native bytes overlap the special
dispatcher IDs; the codec distinguishes text payload from top-level commands.

On GBA, text-bearing commands such as `message`, the `msgbox` shorthand,
`messageautoscroll`, `braillemessage`, `bufferstring`, and `loadhelp` use the
same referenced-resource bar as Crystal. Opening one produces a TEXT tab with
editable `text "..."` source and an explicit `text_end`. The compiler uses the
active game's text table, preserves the `$FF` terminator, and retains the
command's exact 32-bit owning pointer for safe relocation.

English and Spanish cartridges use the common Generation III Western table;
Japanese cartridges load the separate Japanese table. If a byte has no unique
text token, source displays it explicitly as `[XX]` (for example `[B8]`).
These raw tokens compile back to the exact byte, preventing visually identical
or transliterated characters from silently changing ROM data.

Crystal event pointers are 16-bit near pointers owned by the event record.
Growing an event script relocates it only within its original 16 KiB
`scriptsBank`, updates that record, and restores both pointer and bytes on Undo.

Manual ROM offsets and CPU-code views have no proven owning pointer, so an
oversized patch is rejected instead of guessing or overwriting adjacent data.
Shorter in-place patches clear their unused tail with `$FF`; Undo restores every
original byte.

Each tab owns its own source draft. Switching to another script, text entry, or
CPU view no longer discards edits that have not been applied. A `●` before the
tab name marks a modified draft. **Revert draft** restores the source generated
from the current ROM without changing ROM bytes; **Apply source patch** is
enabled only while the active draft differs from that generated source.
Compiler errors leave the draft intact so it can be corrected.

Bookmarks preserve the active offset, EVENT/TEXT or Original view, script
kind, and instruction mode. Opening a bookmark therefore cannot reinterpret a
Red/Blue text location as an event script or change an ARM tab to Thumb.

Unapplied drafts participate in the project dirty state. Opening another ROM
or closing the page warns even when no ROM byte has been changed yet. Download
also warns that drafts are not included until **Apply source patch** succeeds;
the user may return to the editor or deliberately download only already-applied
changes.

## Experience

Simple experience opens a shared **Visual logic** document. Verified commands
become readable action nodes such as *Show dialogue*, *Start battle*, *Move
character*, *Play sound*, conditions, and flow links. Addresses, raw bytes,
architecture controls, source directives, and hexadecimal operands are hidden.
Selecting a node still identifies its exact decoded command; unknown data is
never given an invented semantic meaning.

Nerd experience exposes the actual ROM-hacking surface: ROM offsets, byte
counts, ARM/Thumb or LR35902 mode, disassembly, editable macro/assembly source,
pointers, and relocation controls. Switching experience does not replace the
active tab or decoder. The graph and the source are projections of the same
decoded records, not separate implementations.

The Nerd source surface uses a lazily loaded CodeMirror editor with line
numbers and PUSH syntax highlighting for comments, labels, strings, decimal
and hexadecimal literals, directives, RGBDS macros, and Generation III event
commands. CodeMirror is presentation only: compilation, relocation, drafts,
and Undo/Redo remain in the independent code library. CodeMirror and the PUSH
language mode are mandatory: if either fails to initialize, the workspace stays
closed and the notification center reports a persistent error with technical
details.

Generation III and Crystal produce semantic nodes from their verified event
tables. Red/Blue text produces nodes from its real text macros. Red/Blue
executable logic remains LR35902/RGBDS and is labelled low-level engine logic;
the editor does not invent a Generation III event language for it.

The library-like `ScriptLogicGraph` document is the base for a future editable
Blueprint canvas with typed ports and validated command writers; its renderer
decision and safety contract live in
[`VISUAL_SCRIPTING.md`](VISUAL_SCRIPTING.md). Both modes use
the same safe relocation and history engine, but raw Apply/Revert controls are
intentionally Nerd-only until visual node edits can be compiled and validated
without risking the ROM.
Code Editor now follows the shared keyboard contract: Undo/Redo outside the
source field operates on applied ROM patches, while the same shortcut inside
the source textarea remains native text undo and never unexpectedly reverts a
ROM command.

## Shared memory-link utility

`MemoryReferenceUtils` is the common boundary for resolving editor resources.
It converts GBA 32-bit pointers and Gen II near/far banked pointers into a
single `{ offset, reference, kind, label }` contract. Codecs discover semantic
relationships; the shared editor renders and opens them. New viewers should use
this utility instead of repeating bank calculations or constructing relocation
descriptors by hand.

`BinaryCodecUtils` is the lower-level companion for command operands. Gen I and
Gen II codecs use it for bounds-checked little-endian arguments from one to four
bytes, source formatting, and range-checked compilation. It does not translate
addresses: keep bank arithmetic in `MemoryReferenceUtils`/family memory classes
and GBA pointer normalization in the GBA codec.

## Visual graph rendering

The Blueprint view now renders typed execution ports and SVG connection paths.
Conditions expose distinct True and False exits, while sequential commands use
one output and one input. Nodes are staggered for readable flow and keep their
semantic fields inside the node instead of drawing a chart over source text.
This remains a view of the verified decompilation graph: branch-target routing,
free-form node placement and graph-to-ROM compilation stay disabled until the
family codec can validate and relocate the resulting control flow losslessly.
